### Problem

The owner trades with CDC Action Zone and is learning Elliott Wave. Before this slice, zones appeared only as the 48-cell tide strip and a zone label on Market watch, and a signal's market context appeared only as words in the Signals expanded row. No screen showed candles, zones, waves and signals together against the price. The roadmap's slice-5 exit test is: "the chart agrees with Market watch on zone and price; Elliott candidates never violate the three hard rules; markers link to signals."

Starting state, verified at `origin/main` on 2026-10-14 (web `976233f`, service `8b18486`, bot `ece175a`, migrations at I):
- **Bars.** `candles` (1m, 180-day retention), the continuous aggregates `candles_15m`, `candles_1h` and `candles_1d`, and the `candles_daily` view (`candles_eod` for a daily base). There was no 4h bar and no 4h indicator row.
- **Indicators.** The bot writes one `indicators` row per closed 15m, 1h and 1d bucket (`close`, `ema12`, `ema26`, `cdc_zone`, `atr14`) within 60 s.
- **Realtime.** `/ws` already forwarded `tick`, `bar` (closed 1m bars, with `o,h,l,c,v` tolerated but unread by the web), `zone` (strip timeframe only), `status` and `signal`.
- **Signals.** `GET /signals` is bound to one day and has no instrument filter.
- **Web.** The Chart placeholder was registered on `/chart` and `/chart/:instrument_id`. `app-tide-strip` always drew 48 slots. The Trade pre-fill needed all four keys (`instrument`, `side`, `qty`, `signal`). Overview had no chart library (D6 there).

**The joined read (`internal/repository/postgres/chart.go`, S1).** `ChartRepo.Bars` picks one statement from a closed map: `15m` → `candles_15m`, `1h` → `candles_1h`, `1d` → `candles_daily`. Each statement is built only from constant relation names, eod expressions and timeframe literals.
```sql
SELECT b.ts, b.o::text, b.h::text, b.l::text, b.c::text, b.v::text, b.eod,
       ind.ts IS NOT NULL, ind.ema12, ind.ema26, ind.cdc_zone, ind.atr14
FROM (
    SELECT ts, o, h, l, c, v, <eod expr> AS eod
    FROM <candles_15m | candles_1h | candles_daily>
    WHERE instrument_id = $1 AND ts <= $2
    ORDER BY ts DESC
    LIMIT $3
) b
LEFT JOIN indicators ind
  ON ind.instrument_id = $1 AND ind.timeframe = '<15m | 1h | 1d>' AND ind.ts = b.ts
ORDER BY b.ts
```

## API

### Conventions (contracts r2 §1)

Both routes mount on the gated market group: `NoStore → ReadyGate → BodyLimit(8 KiB) → RequireSession → RequireRole("admin") → RequirePasswordChanged`, through `mountChart` in `internal/app/router.go`. They are GETs, so no CSRF header is needed.

- **Queries** are strict (`parseQuery`): an unknown, repeated (`duplicate`) or unparsable parameter is `400 invalid_request` with `details.field`.
- **Bodies** are snake_case. Instants are RFC 3339 UTC. Absent values are `null`, never omitted.
- **Decimals are strings.** Candle prices and volume are the stored numeric text (`"182.10"`). Indicator values are the stored double written shortest (`strconv.FormatFloat(f, 'f', -1, 64)`), and NaN or Inf is `null`, logged as `indicator_value_not_finite`.
- **Zones:** `buy`, `pre_buy_2`, `pre_buy_1`, `pre_sell_1`, `pre_sell_2`, `sell` or `null`.
- **The closed rule:** a bar is closed at T when it is an eod bar or `ts + timeframe ≤ T`. On the chart route, T is `generated_at`.
- **No new error code.** `unknown_instrument` (404) and `timeframe_unavailable` (422) are reused. Only their "When" text in the README error table changed. `TestCodes_Contract` passes.
- **Route count.** `TestRouter_ForcedChangeGatesNewRoutes` now counts **45** gated routes (42 production + 3 test probes), up from 43.

### `GET /instruments/{id}/chart`

- **The read.**
  - **Head read (no `to`):** reads `max(limit, 1000)` bars at or before `generated_at` in one statement.
  - **Earlier read (`to` set):** reads `limit` bars at or before `to`.
  - `bars` returns the newest `limit`, oldest first. Each bar carries `ts, o, h, l, c, v, ema12, ema26, cdc_zone, atr14, closed`; all four indicator values are `null` when the row is missing.
  - `last_is_partial` is true when the last bar is not closed.
- **Analysis window (CH-OD-1).** `right_now`, `elliott` and the regime use the closed bars among the newest 1,000 read, so `limit=8` gives the same overlays as a default read (`TestService_Chart_AnalysisWindow`).
- **`right_now`** (head read only).
  - `zone`, `zone_age` and `zone_since` come from the trailing run over the newest ≤ 48 closed bars that have an indicator row (CH-R2).
  - `ema12`, `ema26` and `atr14` come from that newest row.
  - `regime` is computed on the chart timeframe.
  - `last {price, ts}`, `change_24h {reference_price, reference_ts, abs, pct}` and `status {mode, stale, session, next_open_at, delay_minutes}` are exactly the Market watch row's at `generated_at`. The service builds them with Market watch's own row builder, called as `(*MarketWatchService)(nil).row(...)` after RF1, so a field read would panic in tests instead of drifting.
  - In the ≤ 60 s before the bot writes a closed bucket's row, the newest closed bar has `cdc_zone: null` while `right_now.zone` still reads the previous row, as Market watch does.
- **`elliott`** (head read): see below. It is `null` with `to` or when the window has no closed bar.
- **`stance`** (head read): `{bot_id, bot_name, bot_status (running|observing|paused), verdict (one of the fourteen C11 values), rule (entry|exit|null), reasons[], timeframe, zone, zone_age, zone_run_started_at, held, pending_order, baseline_at, evaluated_at, decision_id, order_id}`, or `null`. The route never creates a bot, account or watchlist (`TestChart_Stance_ScopedAndNoCreate`).
- **Earlier read:** `right_now`, `elliott` and `stance` are all `null`. An empty `bars` means there is nothing earlier.

### The `elliott` object and the labeller (`internal/market/waves`, contracts r2 §3)

```json
{"timeframe":"1h","threshold_pct":"2.5","as_of":"2026-10-14T05:00:00Z",
 "pivots":[{"ts":"2026-09-30T14:00:00Z","price":"171.2000","kind":"low"}, …],
 "candidates":[{"id":"impulse-5","kind":"impulse","stage":"Impulse, in wave 5","direction":"up","fit":"0.58",
   "points":[{"label":"0","ts":"…","price":"171.2000","forming":false}, …, {"label":"5","ts":"…","price":"189.1000","forming":true}],
   "invalidation":{"price":"183.4000","side":"below","wave":"4"},
   "fibonacci":{"from":"171.2000","to":"185.9000","levels":[{"ratio":"0.382","price":"180.2846"},{"ratio":"0.5","price":"178.5500"},{"ratio":"0.618","price":"176.8154"}]}}],
 "sentence":"Candidate counts are not forecasts."}
```

- **Ids, kinds and stage words** (exact; U+2013 en dash):

  | id | kind | stage |
  |---|---|---|
  | `impulse-complete` | impulse | "Impulse, complete 0–5" |
  | `impulse-5` | impulse | "Impulse, in wave 5" |
  | `impulse-3` | impulse | "Impulse, in wave 3" |
  | `corrective-complete` | corrective | "Corrective A–B–C, complete" |
  | `corrective-c` | corrective | "Corrective A–B–C, in wave C" |

- **Field rules.**
  - `fit` is a string with exactly two decimals in `["0.30", "1.00"]`.
  - A forming point carries the newest closed bar's `ts` and close, with `forming: true`.
  - `invalidation.wave` is `4`, `2` or `B`; `side` is `below` (bullish) or `above` (bearish).
  - `fibonacci` is `null` for a corrective.
  - `sentence` is always exactly "Candidate counts are not forecasts."
- **Algorithm (pinned; the later bot port follows it).** All arithmetic is exact: `big.Rat` on the stored decimal text, with no floating point in the package.
  - **W1 Zigzag on closes.** The first `c[i]` at least `t` from `c[0]` sets the direction. A move of at least `t` against the extreme confirms a pivot. Pivot 0 is bar 0. A provisional final pivot is added only when the extreme is not the last bar. Fewer than three pivots means no candidate, and `waves_input_too_short` is logged at debug by the service.
  - **W2 Hypotheses** over the newest pivots, with `C` (the newest closed close) as a forming point where needed.
  - **W3 Rules.** Each present wave moves in its own direction.
    - R1 `q2 > q0`.
    - R2 `|p3−p2| ≥ min(|p1−p0|, |p5−p4|)`, with the forming 5 counting; only `> 0` for `impulse-3`.
    - R3 `q4 > q1`.
    - Corrective: `qA > q0`, `q0 < qB < qA`, and `qC > qA` for complete or `qC > qB` for in-wave-C.
  - **W4 Invalidation.** The level is point 4, 2 or B. A candidate is dropped when `q(C) ≤ q(invalidation)`.
  - **W5 Fit** `= 0.30 + 0.70 × mean(max(0, 1 − |r − ideal| / tolerance))`, rounded half away from zero to two decimals. The (ideal, tolerance) pairs: r2 (0.5, 0.5), r3 (1.618, 1.0), r4 (0.382, 0.4), r5 (1.0, 0.8), rB (0.5, 0.5), rC (1.0, 0.8).
  - **W6 Ranking.** By two-decimal fit, then complete before forming, then impulse before corrective, then `impulse-5` before `impulse-3`. The first two are returned.
  - **W7 Fibonacci.** Impulse only, on the leg 0→5, 0→3 or 0→1: `price = to − (to − from) × ratio`.
- **The `Tunables` table** (`waves.Tunables`, `tunables.go`) holds every constant as decimal text:
  - `ThresholdPct`: 15m `"1.2"`, 1h `"2.5"`, 1d `"6"`.
  - The six fit `Ideal`s above.
  - `FitBase "0.30"`, `FitWeight "0.70"`, `FitDecimals 2`.
  - `MaxCandidates 2`.
  - `FibonacciRatios ["0.382", "0.5", "0.618"]`.
  - `TrendATRMultiple "0.25"`, `VolPercentile 80`, `VolLookback 100`, `MinATRRows 20`, `ATRPctDecimals 2`.

  Changing a value is a fixture and contract change, made in the service and the bot at once.

### Regime (contracts r2 §4)

`{"trend": "up" | "down" | "range", "vol": "normal" | "high", "atr_pct": "0.83"}`, or `null`.

- **R** is the newest closed bar whose row has finite `ema12`, `ema26` and `atr14`. The population is the finite `atr14` values of the newest ≤ 100 closed bars up to and including R.
- **Null** when there is no R or fewer than 20 values.
- **Trend** is `up` when `ema12 − ema26 > 0.25 × atr14`, `down` when `ema26 − ema12 > 0.25 × atr14`, else `range`.
- **Vol** is `high` when `atr14 ≥` the nearest-rank 80th percentile, else `normal`.
- **`atr_pct`** is `100 × atr14 / R's close`, rounded to two decimals.
- **Web words:** "Trend up, normal vol", "Trend down, high vol", "Range, normal vol".

### `ChartService` (`feat-chart/data/chart.service.ts`, component-provided, SE-5)

- **Reads.** Keyed on the route parameter (S13) and `tf`/`off`/`on`, through `ChartApi` (`data/chart-api.service.ts`) and `httpResource`s:
  - `GET /market-watch` (select, header identity, FR-CH-WEB-003);
  - the head (default limit);
  - `GET /instruments/{id}` once for an off-watchlist instrument (CH-W-2);
  - `GET /instruments/{id}/signals?from={first loaded bar ts}&limit=200`;
  - earlier pages, read imperatively.
- **First open.** The first head read waits for `/market-watch` to learn the strip timeframe, unless the link asks for 1D.
- **Readers.** `data/chart.model.ts` has strict readers that refuse a whole body on any of these: a non-string decimal; an unknown zone, verdict, stage, kind, side, wave, trend or vol; a `fit` outside `["0.30","1.00"]` or without two decimals; more than two candidates; more than 5,000 bars; a missing key.
- **Leaf module.** `data/elliott.model.ts` (added in fix round 1, F7) holds the Elliott and regime readers that both the chart model and the Signals model import, so neither imports the other.
- **Earlier bars** (CH-W-23). Reaching the first loaded bar reads `to = first ts − 1 s, limit=1000` once, prepends, and shifts the range so the same bars stay in view. It also re-reads signals with the new `from`. It stops on an empty or short answer, or past 180 days of intraday history before the head's `generated_at`. A failure stops further reads until *Try again*.
- **S14 timeframe switch.** Keeps the centre instant at the centre with the same visible bar count, clamped to the loaded bars.
- **Errors by code** (CH-W-22). Only a `404 unknown_instrument` is the unknown state; a `404 not_found` and every other failure is the error state. A failed background reload keeps what is shown (MW-20).
- **`headLoads`** is a `linkedSignal` on the chart key (fix round 1, F1), so a later visit never opens on eight bars.
- **The chosen candidate** survives re-reads of the same chart while it is still offered (CH-BUILD-8).
- **"Now"** for relative words is the newest `generated_at` the store has read. There is no `Date.now()` or argument-less `new Date()` in `feat-chart/` or `elliott-words.ts` (a `lacks` check).

### The engine seam and the canvas (`feat-chart/engine/`, `chart-canvas.ts`)

- **`CHART_ENGINE`** (`engine/chart-engine.ts`) is an `InjectionToken` over a small interface: create, set bars/EMAs/markers/price lines/primitive, update the forming bar, crosshair and range calls, subscriptions, apply a palette, destroy.
- **`lightweight-engine.ts` is the one file that names `lightweight-charts`.** It uses `import type` plus one dynamic `import()` after the first render, enforced by the `lib-imports` check. Vitest stubs the engine, since jsdom has no canvas.
- **Library options:**
  - `attributionLogo` on, a transparent background, kinetic scroll off, last-price animation off;
  - `handleScroll: { vertTouchDrag: false }` (F10), so a vertical touch drag scrolls the page;
  - `addSeries(CandlestickSeries)` with per-bar `color`/`borderColor`/`wickColor`;
  - two `LineSeries` for EMA 12 (`--text`) and EMA 26 (`--text-3`) at 1.2px, through a widening cast because the typings take whole pixels;
  - `createSeriesMarkers` for signals;
  - `createPriceLine` for the invalidation and Fibonacci levels.
- **Bar colours** (`util/chart-bars.ts`):
  - A zoned up bar is hollow (`--surface` fill, zone-coloured border and wick).
  - A zoned down bar is filled with the zone colour.
  - A no-zone bar (warm-up, a row not yet landed, or the forming bar) has no fill and a `--line-2` border.
  - With CDC off, bars are neutral: `--text-2`, or `--surface` for an up bar.
- **Palette** (`util/chart-palette.ts`, CH-W-6). Each zone's computed `--zone` is read from a probe element carrying its `zone.css` class. Every other colour, and the type, comes from `getComputedStyle(document.documentElement)`. All of it is re-read on a theme change. No TypeScript holds a colour literal or names a `--z-*` token.
- **Labels** (CH-BUILD-9, CH-BD-2):
  - The candles' and EMA 26's last-value labels sit on `--text-2`, and the candles' label is titled with the symbol.
  - Level labels write in `--surface` on `--text-3`.
  - Price lines are sparse-dotted (CH-BUILD-2).
- **Markers.** An up arrow in `--up` below the bar, a down arrow in `--down` above it, a `--text-2` circle for neutral. There is no outline (CH-BUILD-3).
- **Elliott primitive** (`engine/elliott-primitive.ts`, assumption A2 held, no SVG fallback):
  - a `--brand` dashed (3 3) 1.2px polyline;
  - 2.6px dots;
  - labels in `--font-display` at `--text-sm`, weight 600;
  - since PF2, each label stroked 3px wide in `--surface` under its glyphs.
- **Bangkok axis** (CH-W-19). Each instant is handed to the library shifted by +07:00, ticks are formatted from the shifted value (`HH:mm`, `d MMM` at day starts, `MMM yyyy` at month starts), and every event and hook value maps back to the real instant.
- **Wrapper** (S11, an SE-17-style exception). One focusable `role="img"` named by the summary and described by the keys sentence; it has no description while it is named by a state (CH-BUILD-11). The library container is its sibling (CH-BUILD-1). The `.chart-tip` tooltip is `aria-hidden`, at most `min(360px, 100% − 16px)`, with its anchor clamped in the frame.
- **`engineFailed`** (fix round 1, F6). A library-chunk or palette failure shows the load error once there are bars; its *Try again* creates the chart again, with "Loading chart…" meanwhile.
- **A theme change** re-sends the bars once with the new zone colours and keeps the view.
- **Performance** (CH-W-24, FR-CH-WEB-013). In every build, the first candlestick `setData` of a load is wrapped in a User Timing measure named `tw-chart-setdata`. 1,000 bars took **1.7 ms** on the production build (authoritative) and 3.5 ms on the development build.

### Realtime (S7)

- **Interest.** The store acquires one `MarketStream` interest for its instrument, released on destroy and replaced on an instrument change.
- **`tick`** moves the header's last price and change (Market watch's `applyStreamMessage` rules) and the forming bar's `c`, `h` and `l` when the tick's `ts` is in the forming bucket.
- **`bar`** (a closed 1m bar). The web's `BarMessage.bar` gained optional `o`, `h`, `l` and `v` (CH-W-11); only a frame carrying all four is folded.
  - The bar folds into the UTC-aligned forming bucket of 15m, 1h or 1d: `o` of the first, max `h`, min `l`, last `c`, summed `v`.
  - A bar past the boundary opens a new bucket. The previous bar becomes closed without a zone, and S8 is scheduled.
  - A 1m bar ending at or before the head's `right_now.last.ts`, or a minute already folded, adds no volume and leaves `c`; it only widens `h`/`l`.
- **S8** (CH-W-10). After a crossing, one `timeframe={tf}&limit=8` head re-read runs at 65 s, and one more at 180 s only if the newest closed bar still has no zone. A `zone` frame triggers it at once, on a daily base too; on a 15m chart, the 1h `zone` frame at the hour triggers it.
- **Merging an S8 page.**
  - It merges by `ts` and replaces `right_now`, `elliott` and `stance` (CH-OD-1).
  - A page that cannot reach the loaded bars triggers a full head read instead (F2).
  - The forming bar keeps the fold's extremes, and keeps its close when the stream's price is newer than `right_now.last` (F3).
- **`signal`** with an unlisted `signal_id` bumps the signals re-read even while one is in flight (the resource aborts it), one read per burst tick (CH-BUILD-10). The marker and item appear when it answers. "Within 2 s" holds unless more than about 20 new ids arrive per second for more than 2 s. No effect writes a store signal (F5).
- **`status`** updates the tag. A `1d`-base instrument folds nothing and still takes `status` and `signal`.
- **Reconnects.** `reconnected` re-reads the head and the signals. `reloadRequested` and `reloadSucceeded(epoch)` behave as on Market watch (MW-2, MW-26). `reconnecting` shows "Reconnecting live prices…".
- **The engine** applies a fold as a single-bar update (no history `setData`). Older candles are patched in place, capped at 32, beyond which it replaces and restores the range. Markers are added in place.
- **Nothing in these updates moves the visible range, scrolls, animates or announces** (MW-23).

### Defects found on the preview and their fixes

**PF1 (`5476985`, plus the lint fix `6bc61c8`).** These were three deterministic failures in PV1 at `4d8de59`, each reproduced 2/2 in isolation.

1. **The marker click did not mark its feed item** (`chart.spec` "links markers and items @hook", development build).
   - *Cause:* `lightweight-charts` 5.2.1's hover arbitration (`hitTestPane`) lets a series drawn above the candles win. An EMA line passing within its 3px hit tolerance took the pointer off a marker it crossed. The engine reported a marker only when the library named one (`lightweight-engine.ts:426`), so the click marked nothing.
   - *Fix:* when the library names no known marker, the engine hit-tests its own placed markers (`markerUnder`). A pixel inside a marker's drawn box, plus the library's 2px tolerance, names that marker; the first in drawing order wins. It acts only on user events, and hover ignores programmatic pointers. Specced in `lightweight-engine.spec`.
   - Code review r4 noted that the circle's hit box is square, about 3px generous at the corners: immaterial.
2. **Earlier bars stopped loading** ("loads earlier bars when the view reaches the first bar @hook", development build).
   - *Cause:* the "reached the first bar" test was `range.from <= 0`. After 500 bars were prepended to 1,000, the library read back a range set to start at 0 as `1.1368683772161603e-13`, so the next earlier read never triggered.
   - *Fix:* `FIRST_BAR_TOLERANCE = 1e-6` bar in `util/chart-range.ts` (`reachesFirstBar`), shared by `chart-canvas.ts`, `chart.ts` and the e2e `atFirstBar` helper. Tested that `0.001` reads as not reached.
3. **A pasted out-of-window Signals day stayed on "Loading signals…" forever** (`signals.spec` "never draws an out-of-window or future day and ends on Today", production build only).
   - *Cause:* this was **pre-existing on `main` at `976233f`**, which fails it 2/2 on production. It was a timing race, not a date dependence. A refused pasted day's late list page was taken as a midnight rollover (`signals.service.ts` ~463/482/1074), so the store picked the refused day again after the URL had dropped it.
   - *Fix:* a first page whose `day` does not answer the request that sent it (`answersDay`: `page.day === (sentDay ?? bangkokDay(generated_at))`) now only updates D0 (`noteAnswer`). It starts no rollover and no re-read, and the resource drops it. Specced in `signals.service.spec`; the new spec fails 1/67 with the guard off.
   - This is a recorded scope extension, included because it blocked PV1b. Follow-ups (code r4, angular r4): also check `loaded.ref === untracked(listRef)`, and restrict the rollover pick to pages with `sentDay === null`.

Also seen: `signals.spec` "opens Add source and returns focus" is flaky on production builds. It is pre-existing (HEAD failed 6 of 12 runs), passed in PV1b r2, and is a follow-up.
